# signals, never verdicts

this component is a lego block. it enumerates instrument facts, cited
and dated, with decay cadences. it is never run standalone, it never
answers "is this fraud", it never qualifies anything as a sure thing,
and it never brands any person or account. this family of components
does not detect fraud and never claims to: the rows are small signals
about infrastructure.

the composition rule, stated once and binding for every integrator:

- a signal is a signal. every row on every branch can be occupied by
  an entirely legitimate person. the author of this registry family
  is a paying proton and fanytel user with .xyz domains, an active
  degoogler running mobile linux and fdroid since middle school, who
  masks cards with privacy.com. every bucket a naive reader might
  call "flagged" has a lawful ordinary resident, and one of them is
  this author.
- signals are never read in a vacuum. one radar never concludes
  anything. which signals combine, and what the combination means, is
  decided outside this component, every time.
- the glue is theirs. how signals are combined, weighted and turned
  into policy is the integrator's work and the integrator's
  responsibility. this repo provides blocks, not judgments, and the
  composition layer belongs to whoever plugs the blocks together.
- absence of evidence is never evidence of absence, and unknown is
  first-class everywhere in this family.
- nothing here is a salem witch trial. there are no verdicts and no
  branding in these tables: cited facts, decay dates, honest notes,
  and the interpretation of all of it is explicitly out of scope for
  this component and its authors.

if you are an integrator and you want a verdict, build it yourself,
own it yourself, and expect to be wrong sometimes. this component
will not do it for you, and it was designed so it cannot.
